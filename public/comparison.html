Same grade sheet. Different control.

An implemented comparison of server-controlled sharing and cryptographic attribute policies.

Explain the difference

Question Normal approach Our ABE approach
Who decides access? Express checks the user's saved role and student ID. The issued attribute key must satisfy the encrypted file's policy.
Where is the file key? The server holds its AES key. A fresh file key is protected by CP-ABE inside each package.
Where is decryption? On the server before download. In the recipient's browser using their private key.
Does copying ciphertext reveal grades? No, ciphertext alone is insufficient. The server-held key can decrypt it. No. The copied package still needs a matching attribute key.
What is the cost? Simple key management and fast AES operations. Additional encryption/decryption time, larger packages, and key issuance.

Five-minute faculty demonstration

  1. Problem: “A student's grade sheet should be readable only by that student or authorized faculty.”
  2. Normal approach: show Student A downloading their sheet and Student B denied by the server.
  3. Our policy: show student_23cs101 OR (role_faculty AND dept_cse).
  4. Real encryption: as faculty, encrypt a PDF in the ABE workspace and save its file ID.
  5. Copied-file test: load Student B's issued key and try that ID. The package arrives, but local decryption fails. Load Student A's key and it succeeds.
  6. Results: show the measurements above and explain the cost of ABE.
  7. Limits: the authority and recipient device must be trusted. This demo uses one laptop. A malicious server that replaces the web application's JavaScript could steal an imported key. Separate client distribution and operating-system isolation are future improvements.

What we contributed

We applied an existing CP-ABE scheme to individual grade-sheet sharing, integrated it with local MongoDB and Express, moved encryption/decryption into the browser, separated authority key issuance from storage, and tested the same access scenario under both approaches.

This is an application-level improvement, not a new cryptographic algorithm. Revocation of previously issued keys and previously downloaded plaintext remains future work. GoFE/FAME is research software; this prototype is for synthetic academic demonstrations.
