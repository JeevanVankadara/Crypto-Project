UNDERSTAND THE BASELINE

From upload to download

  1. Faculty uploads a PDF.

    The server checks the faculty account and the student’s department.

  2. The server encrypts the file.

    The encrypted PDF is saved on disk. MongoDB stores its student ID, department, title, and random file ID.

  3. A user requests a grade sheet.

    The server loads the user’s saved identity and checks whether they own the sheet or teach in its department.

  4. The server decrypts approved downloads.

    A denied request gets an error and no PDF. Every download decision is recorded in the activity log.

What this version demonstrates

Students receive their own records, and faculty receive their department’s records. The storage files are encrypted, but the server can decrypt every file because it owns the key.

Next phase: use attribute-based encryption to make the decryption capability depend on a user’s issued attribute key.
